# 套餐商城（卖家套餐、审核与分账）

聚合网关阶段 4 的功能说明。成员可以发布用自己的供应商服务的套餐，Owner 审核通过、成员上架后，其他用户在套餐页用现金余额购买；成交款按抽成比例扣除后记入卖家的现金余额。

整个功能由商城开关控制，默认关闭。关闭时本页的界面和接口都不可用（接口返回 404），卖家套餐不能购买或续费；平台套餐照常销售，与升级前一致。成员的供应商、出口和自用见[我的供应商](tenant-providers.md)。

## 开启与设置（Owner）

侧栏“管理 › 商城管理”。

- **商城设置**（`GET/PUT /admin/market/settings`）：
  - 开启商城：同时开放成员的供应商、自用、卖家套餐和购买成员套餐；需要已配置账号出口服务。
  - 抽成比例：0–1，最多 6 位小数（0.1 即 10%）。每笔成交按当时的比例计算并记入成交记录，之后修改不影响已成交的订单。
  - 每人供应商上限（0–256）、每人套餐上限（0–100，已删除的套餐不计）、每人出口服务器上限（0–32）、是否允许成员添加 API Key 供应商。
  - 保存需要 5 分钟内验证过身份，并带上当前设置版本；版本不符说明别人刚改过，刷新后再保存。
- 侧栏“商城管理”旁的红色数字是待审核的套餐数。

## 发布套餐（成员）

侧栏“我的供应商 › 我的套餐”。Owner 的套餐是平台套餐，在“套餐”页维护，不使用本页。

1. **发布**：填写名称、说明、每期价格、周期、适用模型、每期额度和最低购买期数。新套餐保存为**草稿**，不会出现在商城。数量受每人套餐上限限制。
2. **供应商范围**：默认“不限制”，即你此刻的全部账号（不含被停用、已删除的）；也可以“指定”部分账号。范围随时可改，从下一次请求起生效，不需要审核，也不影响已售订阅的续费。
3. **提交审核**：草稿或被驳回的套餐可以提交，状态变为“待审核”。
4. **上架 / 下架**：上架意向由你控制。只有同时满足“已通过审核、已上架、未被 Owner 下架、你的账号状态正常、商城已开启”时，套餐才在商城销售。下架后已售订阅照常服务和续费。
5. **修改**：改价格、额度、周期、模型、名称或说明时，已通过（或已驳回、待审核）的套餐重新进入“待审核”，审核期间暂停销售，也不能续费；草稿修改后仍是草稿。只改上下架或供应商范围不需要审核。
6. **删除**：已售订阅照常服务到期，但不能再续费。

### 卖家的责任

- 订阅只由你的账号服务。买家的这份额度用完、而请求成本超出剩余额度时，差额记为未覆盖，由你承担，不会扣买家的现金。
- 你的账号全部不可用（被停用、删除或额度保护暂停）时，买家的这层订阅暂时无法使用，请求会落到买家自己的其他资金（只由平台账号服务）。
- 如果你的范围里有 API Key 供应商，买家购买前要确认“对方能看到经它处理的请求内容”。

### 销售收入与用量

- **销售收入**：每笔购买或续费一行，显示成交额、抽成（含当时的比例）和到账金额，以及合计。买家只显示为“买家 #N”，N 是该买家第一次购买你的套餐的顺序；你看不到买家的名字或账号。
- **到账**：净额立即记入你的现金余额（流水类型“套餐销售收入”，不含买家信息），可以像充值一样用于购买套餐或按量付费；不支持提现。抽成为 100% 时没有到账流水。
- **查看用量**：按账号汇总由这个套餐的订阅付费的请求数、Token 数和扣除额度，以及有效订阅数。不显示买家。

## 购买（所有用户）

商城开启时，“套餐”页即商城：平台套餐在前，其后是已上架的成员套餐。成员套餐的卡片显示卖家、说明、各协议的官方账号和第三方 API 数量。

- 不能购买自己发布的套餐。
- 标有“含第三方 API 供应商”的套餐，购买（和续费）时须勾选确认：对方能看到经它处理的提示词和回复。
- 确认记在这份订阅上，可以在“额度与订阅”的订阅卡片上随时撤回或重新确认，从下一次请求起生效。卖家的 API Key 供应商只为确认过的订阅服务：卖家售出后才把它加进范围时，卡片会提示，你确认之前它不处理你的请求，订阅只由卖家的官方账号服务。
- 价格、周期、额度、起购期数和续费规则与平台套餐相同；每次购买新增一份独立订阅。
- 买到的订阅在扣费时单独成为一层，排在个人余额之前，只为卖家的账号付费（见[阶段 3 验证](aggregation-gateway-stage3-validation.md)的规则 5）。

## 审核与处置（Owner）

“商城管理”页：

- **套餐审核**：待审核的套餐按提交时间排列，显示卖家、说明、价格、模型和供应商构成。“通过”后，卖家已上架的套餐立即开始销售；“驳回”必须填写原因，卖家在自己的套餐卡片上看到它。审核基于提交时的版本：卖家在此期间又修改了套餐，审核会提示已变更，需要刷新后重新审核。
- **成员套餐**：全部成员套餐及其状态、有效订阅数。“强制下架”须填写原因；被下架的套餐停止销售，卖家不能自行重新上架，已售订阅照常服务。“恢复”后卖家可以重新上架。
- **全部成交**：显示每笔成交的卖家、买家、成交额、抽成和卖家到账，以及合计。

卖家的账号被 Owner 停用（用户状态不再正常）时，该卖家的全部套餐停止销售，已售订阅的这一层暂时没有可用账号。

买家已付费、订阅仍有额度，但卖家此刻没有可用账号时，Gateway 产生 `subscription_layer_empty` 告警（每个订阅、每个协议一条），
Owner 可据此联系卖家或下架套餐、人工处理买家余额。见[运维手册](operations.md#聚合网关告警)。

成交记录跟随信息清理：早于截止时间、且买家与卖家两条流水都已清理的成交记录一并删除。仍有套餐、套餐仍被订阅
引用或出现在成交记录中的成员不能永久删除，见[运维手册](operations.md#成员的停用与永久删除0055)。

## 金额规则

- 成交额 = 单价 × 本次期数（与平台套餐相同）。
- 抽成 = 成交额 × 抽成比例，**向下取整到 12 位小数**；卖家到账 = 成交额 − 抽成。三者都是精确的十进制数，记入 `marketplace_sales`。
- 一次购买在一个事务里完成：按用户 ID 顺序锁定买家和卖家的账户（两个成员互相购买也不会死锁），扣买家现金，新增订阅，给卖家新建一笔现金额度并记流水，写成交记录。任何一步失败都整体回滚，例如余额不足时卖家不会收到款项。
- 同一个 `operation_id` 重复提交只执行一次，返回第一次的结果。

## 接口

| 方法与路径 | 用途 | 权限 |
|---|---|---|
| `GET /admin/market/plans` | 在售套餐（平台与成员） | 已登录 |
| `GET /admin/me/plans` | 我的套餐、范围与可选账号 | 成员 |
| `POST /admin/me/plans` | 发布（草稿） | 成员，近期验证 |
| `PUT /admin/me/plans/{id}` | 修改（含 `version`） | 成员，近期验证 |
| `DELETE /admin/me/plans/{id}` | 删除（`operation_id`、`version`） | 成员，近期验证 |
| `PUT /admin/me/plans/{id}/provider-scope` | 供应商范围 | 成员，近期验证 |
| `POST /admin/me/plans/{id}/submit` | 提交审核（`version`） | 成员，近期验证 |
| `PUT /admin/me/plans/{id}/listing` | 上架或下架（`operation_id`、`version`、`active`） | 成员，近期验证 |
| `GET /admin/me/plans/{id}/usage` | 套餐用量（按账号） | 成员 |
| `GET /admin/me/sales?limit=&offset=` | 销售收入（买家匿名） | 成员 |
| `POST /admin/billing/me/purchases` | 购买，可带 `acknowledge_third_party` | 已登录，近期验证 |
| `POST /admin/billing/me/subscriptions/{id}/renewals` | 续费，可带 `acknowledge_third_party` | 已登录，近期验证 |
| `PUT /admin/billing/me/subscriptions/{id}/third-party-consent` | `{"acknowledged": bool}`，确认或撤回卖家 API Key 供应商（只接受本人的成员套餐订阅） | 已登录，近期验证 |
| `GET /admin/market/reviews` | 待审核与全部成员套餐 | Owner |
| `POST /admin/market/reviews/{id}` | `{"decision": "approve"|"reject", "note", "version"}` | Owner，近期验证 |
| `PUT /admin/market/plans/{id}/suspend` | `{"suspended": bool, "reason"}` | Owner，近期验证 |
| `GET /admin/market/sales?limit=&offset=` | 全部成交 | Owner |

成员访问 Owner 接口得到 403；Owner 访问成员的 `/admin/me/plans`、`/admin/me/sales` 也得到 403。读写他人的套餐一律返回 404，不暴露是否存在。

主要错误码：`marketplace_disabled`（404）、`seller_plan_limit`、`plan_not_on_sale`、`third_party_acknowledgement_required`、`seller_plan_suspended`、`plan_review_state`、`billing_plan_changed`（均为 409）、`self_purchase`（400）。

## 审计

- `billing.plan_create` / `billing.plan_update` / `billing.plan_delete`：卖家套餐的增删改（与平台套餐共用，操作人为卖家）。
- `marketplace.plan_submitted`、`marketplace.plan_reviewed`（决定与备注）、`marketplace.plan_suspended`（原因）。
- `marketplace.plan_sold`：每笔成交，含买家、卖家、成交额、抽成比例、抽成与到账。
- `billing.plan_purchase` / `billing.plan_renewal`：买家一侧的购买与续费。
- `billing.third_party_consent_changed`：买家确认或撤回第三方 API 供应商（含套餐 ID）。
